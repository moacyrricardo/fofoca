What it does

Notes from your calls, without sending them anywhere

Local meeting-notes apps usually assume a big GPU or an Apple Silicon Mac. fo-foca starts from the other end: it measures what your hardware can actually do and picks the best setup that fits.

Transcription

Records your microphone and the system audio (Meet, Zoom, Teams, anything) and transcribes it locally with Whisper, live, while you talk.

Summary

A local LLM writes a "summary so far" during the call and a final summary at the end, grounded in the transcript so every claim can be checked.

To-dos & tasks

Action items, decisions, names, numbers and dates pulled out of the meeting.

100% local

Audio, transcripts and notes never leave your computer. Models run as local servers on your GPU or CPU.

Fits your hardware

Choose where each model runs (GPU, CPU, or both on a 2 GB GPU taking turns); a GPU memory meter shows what fits. Automatic hardware probing and benchmarking is planned

Fast and light

A native desktop app (Rust + Tauri), not a browser in a box.

How it works

Two tracks in, summary and tasks out

Your mic and the system audio are recorded on separate tracks, so your own lines are labelled from the start. Models run as separate local servers that fo-foca loads, unloads and swaps without restarting.

Summary + tasks

  During the call

  • Speech-to-text with whisper.cpp (large-v3-turbo), in 30 s chunks.
  • You vs. them from the separate tracks.
  • Summary so far with a small open-weight model (Qwen3.5), on demand or every few minutes.

  After the call

  • Speakers: the system track is split per speaker (Pessoa 1, Pessoa 2…) by a small CPU model, then aligned with the transcript. Rename them; calendar names are suggested.
  • Final summary & tasks over the full, speaker-labelled transcript.

Small GPU? It swaps.

When both models fit in VRAM they stay loaded. When they don't, Whisper stays on the GPU while you talk and the LLM is swapped in for summaries — about 3 seconds. Detect → Plan → Verify → Fall back, and Settings shows what was chosen and why.

Install

Install on Linux

Linux x86-64, test builds. Takes a few minutes plus the model download (~1.9 GB).

Install the system pieces

Debian / Ubuntu package names. With an NVIDIA GPU, use the NVIDIA driver, which includes Vulkan.

sudo apt install pipewire-bin mesa-vulkan-drivers libwebkit2gtk-4.1-0

Download the models and engines

Get fofoca-setup.sh from the release above. Everything goes to ~/.local/share/fofoca/, where the default config looks.

  • llama-server (llama.cpp, Vulkan) is downloaded.
  • whisper-server is built from source (whisper.cpp ships no Linux build), which needs sudo apt install git cmake build-essential glslc libvulkan-dev.

Run fo-foca

Check the models

In Settings → Models, check that every row is green, and pick the GPU for each engine.

Status

Where it is

Linux first (PipeWire); Windows and macOS are planned. Any GPU that works with Vulkan should be usable — NVIDIA, AMD or Intel — or CPU only. Hardware reports and pt-BR test recordings are very welcome.

Fidelity basis

Composed from the app's design system: tokens and the .card .btn .chip .seg .who .dot .spin classes copied from app/src/app.css, the real logo (assets/logo.jpg) and icons (assets/icons/*.png), embedded. Copy is from README.md, tightened. Dark-only, like the app.

Pinned items

  • 1 · Logo as hero: the logo image is the headline art; its navy background matches --navy closely, but not exactly.
  • 2 · Release card (invented): the real page calls GET api.github.com/repos/moacyrricardo/fofoca/releases?per_page=10 and takes the newest non-draft one, including flagged pre-releases (which /releases/latest skips). It's a test build when flagged or when its tag has a suffix (v0.1.0-pr32): today's release is only named a pre-release, not flagged. Buttons come from the release's assets, matched by suffix (.AppImage, .deb, setup.sh), because the file names carry the version. If the API is unreachable or rate-limited (60/h per IP), it falls back to a link to /releases. Use the shell's "Release API" buttons to see each state. The pre-release sizes and date are real; the 0.2.0 stable release is invented.
  • 3 · Transcript + tasks teaser (invented): drawn with the app's .who/.dot styles, all invented lines. It stands in for a real screenshot; the build could swap in a screenshot of the fake backend (npx vite preview), never real meeting data.
  • 4 · Pipeline: replaces the README's mermaid chart with plain HTML nodes, so the page needs no JS library.
  • 5 · Setup-script switcher (invented): the README's three command lines, behind the app's .seg control.
  • Status list: one row per shipped/planned item, grouped from specs/CATALOG.md (done = ✓, todo = ☐, concern = ?).
  • 6 · AppImage / .deb switcher (invented): same pattern for step 3.

Left out / substituted

  • The README's Development and Contributing sections: they stay in the README, and the footer links to the repo.
  • Font: same stack as the app (Nunito → system rounded fallbacks). The app doesn't bundle Nunito either.
  • Links are fake (they show a toast). Copy buttons only show a toast.
  • Responsive layout uses container queries so the shell's Phone frame shows the mobile layout; the real page would use plain media queries.
